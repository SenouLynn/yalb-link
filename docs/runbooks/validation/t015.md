# T-015 evidence — decoded flight state the display no longer discards

This runbook preserves the recorded procedure, results, and limitations. Raw
Captures for this run were pruned; the results below stand without them.
Artifact comparisons require captures from an available or newly repeated run.

Collected 2026-09-09 against Compose Copter SITL (`Copter-4.7.0`, SYSID 1,
`HOME_LOCATION 37.7749,-122.4194,10,0`), the mock fixtures, and a recording
replayed after a backend restart.

## Method

SSE was counted directly rather than through the UI:

```sh
curl -sN --max-time 45 http://localhost:8080/api/events
```

Screenshots were driven over CDP rather than by flags, because the live page
holds an open SSE connection and never goes network-idle — `--virtual-time-budget`
does not return on it. Chrome was launched with
`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`; `--disable-gpu`
blanks the page by denying MapLibre a WebGL context. Console and exception
events were subscribed in the same session: **no errors or exceptions were
logged in any capture**.

## Findings that changed the implementation

**`HOME_POSITION` is an event, not a stream.** The baseline capture contained
exactly one in 45 s. Under `TELEMETRY_TTL_MS` (5 s) home would dash five seconds
into every flight and never return, while the altitude tape beside it still read
"above home". It is therefore declined in `DefaultRates` — requesting a value
that does not change is noise on the link — and aged against `HOME_TTL_MS`
instead. `live-home.png` shows it reading correctly at 9 s.

**Home may legitimately never arrive.** If the backend starts after the vehicle
set home, no `HOME_POSITION` is sent and the group shows its absence sentence.
`live-recovered.png` is that case. Recovering it would need
`MAV_CMD_GET_HOME_POSITION`, an outbound command, and so is outside this
read-only card.

**The mock's health families were outside the freshness TTL.** They were sent
every tenth cycle, which was exactly `TELEMETRY_TTL_MS` before this card and
went over it when guidance added a sixth frame per cycle — battery, GPS, EKF and
radio all dashed at `?source=mock` despite being sent. The cadence is now every
fifth cycle and `mock.test.ts` fails if any family's worst gap reaches the TTL.

## Limit: `RADIO_STATUS` cannot be demonstrated on this stack

`RADIO_STATUS` originates in a SiK modem. Compose carries MAVLink over UDP with
no radio in the path, and the captures confirm zero arrivals. Its acceptance is
fixture-based (`mock-1440.png`), and its absence on SITL is not a defect. No
live session should be spent chasing it.

## Defect found, not fixed here

After a SITL restart the vehicle returns on a new UDP source port. The backend
logs `SOURCE_CONFLICT`, keeps treating the vehicle as present because heartbeats
never stopped, and so never re-runs the discovery path that issues rate
requests. Every requested family goes silent, not only the one this card added.
Raised as [T-023](../../tasks/cards/T-023-rate-requests-after-source-change.md).


### Subsequent protocol corrections (T-024)

The original captures establish rendering and freshness, not the correctness of
nonzero Plane guidance errors. Review corrected the error direction labels
(positive means below target), applied Plane/QuadPlane airspeed error scaling,
changed radio buffer wording to free space, and corrected signal/noise unknown
values to 255. Historical screenshots are retained as recorded; their old labels
are superseded by [T-024](../../tasks/cards/T-024-correct-telemetry-interpretation.md).
T-024 records automated regression results; these corrections have not been
revalidated in a new live SITL capture.
