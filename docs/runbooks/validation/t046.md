# T-046 native serial acquisition

The backend can enumerate and open local serial ports over HTTP, with UDP and
operator commands disabled. Serial frames enter the same bridge, fleet fold,
addressed mission coordinator, SSE stream and recording sink as UDP frames.
Profiles, connection UI, automatic retry and physical USB/radio acceptance are
separate tasks (T-047/T-048/T-049 and T-028/T-031).

## Local use

Build on macOS with CGO and the Apple C toolchain/SDK:

```sh
CGO_ENABLED=1 go build -o /tmp/gcs ./cmd/gcs
GCS_MAVLINK_UDP_BIND= GCS_COMMANDS_ENABLED=false /tmp/gcs
curl -s http://localhost:8080/api/connections/devices
curl -s http://localhost:8080/api/connections
```

Copy an exact `id` from inventory, then select its actual baud rate:

```sh
curl -s -H 'Content-Type: application/json' \
  -d '{"device_id":"serial:/dev/cu.example","settings":{"baud_rate":57600}}' \
  http://localhost:8080/api/connections/connect
curl -N http://localhost:8080/api/events
curl -s -H 'Content-Type: application/json' \
  -d '{"id":"serial:/dev/cu.example"}' \
  http://localhost:8080/api/connections/disconnect
```

`GCS_HTTP_ADDR` optionally changes the HTTP listen address (default `:8080`).
`GCS_SERIAL_PATHS` optionally adds an OS path-list of explicitly configured
serial character devices to native inventory, including non-enumerated UARTs
and test PTYs. These candidates must still exist and be character devices;
symlinks are resolved and duplicate paths removed. This is not profile storage.
Paths exposed over HTTP must come from inventory, never an arbitrary request
path. Normal USB discovery requires no extra path configuration.

A silent open port stays OPEN_AWAITING_TRAFFIC indefinitely. Any valid non-GCS
frame establishes REPORTING, even without HEARTBEAT. More than 60 seconds
without a valid frame establishes INTERRUPTED; new frames restore REPORTING.
Fleet liveness and individual reading freshness remain separate. Inventory
removal is DEVICE_LOST; an I/O error without removal evidence is
TRANSPORT_FAILED. Explicit disconnect is RELEASED, and does not retry.

## Controlled expectations

The standard-library Python harness creates a PTY, launches a temporary backend
on a free loopback HTTP port with recording enabled, UDP/commands disabled, and
selects the PTY using the public API. It never opens attached aircraft devices.
Expected before execution:

- Native startup, HTTP acquisition and each telemetry transition within 8 s.
- Two independent system IDs (41 and 42) in the real fleet/telemetry stream.
- Fragmented valid ATTITUDE without heartbeat proves REPORTING without fleet
  discovery; malformed bytes and initial silence do not.
- With `--check-silence`, INTERRUPTED within 63 s of the last valid frame,
  including the one-second sweep; stale route attribution expires.
- Duplicate connect keeps the original open timestamp. Late SSE subscribers
  receive the current acquisition state. Disconnect/reopen resumes observation.
- Independent MAVLink CRC and payload decode allows GCS HEARTBEAT and addressed
  MAV_CMD_SET_MESSAGE_INTERVAL only until a mission download is requested;
  then MISSION_REQUEST_LIST/INT/ACK are allowed. Any other message/command fails.
- Serial observations produce actual SQLite recording rows. Explicit disconnect
  releases the port to a second opener, followed by no outbound traffic for 1.2 s.
- PTY master removal produces DEVICE_LOST or an observed TRANSPORT_FAILED, never
  an inferred radio/aircraft cause. Process shutdown completes within 5 s.

Permission-denied and busy cases are **injected OS errors** in Go tests, not
claims of observed physical ownership. Net-pipe tests cover stopped consumers,
including Close concurrent with a blocked Disconnect, and goroutine leak checks.
A shared-bridge test moves one identity between two live connections, verifies
address attribution and stale-route retirement, and reopens without ending the
fleet pipeline. A rate-request regression checks disconnect during acquisition.

## Reproduce native and Linux checks

```sh
go test -race -timeout=2m ./internal/connection/... ./internal/codec/... \
  ./internal/bridge/... ./internal/routes/... ./internal/stream/... \
  ./internal/mission/... ./cmd/gcs/...
CGO_ENABLED=1 go build ./...
CGO_ENABLED=1 go build -o /tmp/t046-gcs ./cmd/gcs
python3 scripts/validation/serial-acquisition.py \
  --binary /tmp/t046-gcs --check-silence
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build ./...
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o /tmp/t046-gcs-linux ./cmd/gcs
make bazel-tidy
bazel test //internal/... //cmd/gcs/...
./scripts/kanban check
```

Linux needs an actual runtime, not just cross-compilation. Run the harness and
Linux binary on a Linux arm64 machine with Python 3, or use an isolated
container with Python 3 and PTY support. This session used the already cached
`sitl-harness-probe:latest` image (Python 3.12.3):

```sh
docker run --rm \
  --mount type=bind,src=/tmp/t046-gcs-linux,dst=/tmp/gcs,readonly \
  --mount type=bind,src="$PWD/scripts/validation/serial-acquisition.py",dst=/tmp/serial-acquisition.py,readonly \
  --entrypoint python3 sitl-harness-probe:latest \
  /tmp/serial-acquisition.py --binary /tmp/gcs --check-silence
```

The image is a local convenience, not a portable dependency. Any Linux arm64
Python environment can run the same standard-library harness and static binary.
No container privilege or real USB device mapping is required for PTYs.

## Plane 4.6.3 QuadPlane through serial

Reuse the built T-027 image in a separate simulator. Distinct serial ports are
required: the image's default `--serial1 tcp:0` would otherwise also bind 5760.
The test peer forwards this simulator's bytes through the PTY; the application
itself opens native serial and has no UDP transport enabled.

```sh
docker run -d --rm --name t046-quadplane \
  -p 127.0.0.1:15763:5760 -e SYSID=4 -e VEHICLE_MODEL=quadplane-tri \
  -e GCS_OUT=tcp:5760 yalb-gcs-ardupilot-sitl-quadplane-tri-4:latest \
  --serial1 tcp:5762
python3 scripts/validation/serial-acquisition.py \
  --binary /tmp/t046-gcs --sitl 127.0.0.1:15763
docker stop t046-quadplane
```

Expect sysid 4 fleet discovery within 20 s, attitude and global position,
mission download and recorded telemetry. Independent harness-originated reads
(sysid 254) confirm AUTOPILOT_VERSION `0x040603ff`, Q_ENABLE=1 and
Q_FRAME_CLASS=7. These profile reads are separated from the backend-originated
(sysid 255) traffic allowlist. No arming, flight or parameter writes occur.

## Results and limits

Executed 2026-09-23 with Go **1.25.0**, native macOS **26.6.2 arm64**
(CGO enabled) and Linux **6.12.76-linuxkit aarch64** (CGO-free production
binary in a Docker runtime, Python 3.12.3). Both full package builds passed.

- Required Go race suite passed, including goroutine leak checks, multi-source
  handoff, fixed UDP release/reopen, and pending channel retirement on disconnect.
- All **10 Bazel backend test targets passed**. `make bazel-tidy` completed.
  The host command exposed Bazel 8.3.1 while the repository pins 8.7.0; used a
  temporary 8.7.0 binary via `PATH=/tmp/t046-tools:$PATH`, without replacing the
  host installation. Gazelle also repaired an existing missing codec test
  dependency on generated GCS types. Existing macOS linker warnings were
  non-fatal; no test or build failure remains.
- Full-duration synthetic PTY harness passed on **both platforms**, including
  the real 60-second interruption and recovery. Each final long run observed
  62 GCS heartbeats, 27 addressed interval requests, one mission-list request
  and one mission ACK; no prohibited traffic. Each produced five recording
  events. Explicit release allowed a second opener; no subsequent outbound
  traffic appeared during the 1.2-second observation. Shutdown measured
  **0.018 s macOS / 0.014 s Linux**, below the five-second bound.
- Final Plane 4.6.3 QuadPlane run passed on the macOS serial path: firmware
  `0x040603ff`, Q_ENABLE=1, Q_FRAME_CLASS=7, sysid 4 fleet, attitude/global
  position, empty mission download, and 11 recorded events. Outbound traffic:
  one heartbeat, nine interval requests, one mission-list request and one
  mission ACK, addressed to sysid 4 / component 1. Shutdown was 0.020 s.
- Initial long-run harness attempts used an SSE read timeout shorter than the
  backend's 15-second keepalive. Corrected it to 30 s and repeated both entire
  60-second scenarios successfully. The independent AUTOPILOT_VERSION decoder
  uses the MAVLink wire offset after both uint64 fields. The SITL peer stops
  feeding the intentionally released PTY while continuing to monitor outbound
  traffic. These are harness corrections, not substituted application evidence.
- The isolated simulator was stopped after verification. No existing Compose
  services or attached flight controllers were modified.
