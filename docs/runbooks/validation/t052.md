# Backward track/Flown-distance repeat (T-052)

## What this checks

T-019 run 3 found the rendered track stepping ~0.7 m backward during steady
northward flight, and the UI's Flown counter reading 256 m against a raw
GLOBAL_POSITION_INT route length of 200.75 m. `fleet/state.ts` appended every
telemetry event's own field partial straight into the accumulated track,
including GPS_RAW_INT fixes that lag behind a fresher GLOBAL_POSITION_INT
already merged into the resolver-facing sample. The fix in `applyTelemetry`
now: prefers a fresh GLOBAL_POSITION_INT over GPS_RAW_INT while it is within
the telemetry TTL, rejects non-increasing observation timestamps per family,
and replaces (rather than double-counts) a same-timestamp GPS fallback point
once global position arrives. `fleet/positionTrack.test.ts` regresses the
interleavings directly; this runbook repeats the T-019 flight to confirm the
rendered track and Flown counter against independently decoded positions.

## Reproduce

Same fixture as [T-019](t019.md): Compose Copter 4.7.0 `+`, home
37.7749,-122.4194,10 m MSL, real-time speed.

```sh
GCS_RECORDING_ENABLED=true docker compose -f docker-compose.yml -f scripts/validation/t019.compose.yml up -d --force-recreate ardupilot-sitl-copter-1
node scripts/validation/observe-motion.mjs docs/temp/evidence/T-052/RUN/browser 240 &
curl -X POST http://localhost:8080/api/recordings/start
/private/tmp/yalb-t019-venv/bin/python scripts/sitl_motion.py --output docs/temp/evidence/T-052/RUN/flight
curl -X POST http://localhost:8080/api/recordings/stop
# wait for the browser job above to exit, then download its recording:
python3 -c "..."  # same recording.json download step as scripts/validation/analyze-motion.py
MOTION_REPLAY_SPEED=2 node scripts/validation/observe-motion.mjs docs/temp/evidence/T-052/RUN/replay 90 'http://127.0.0.1:3000/?source=replay&recording=ID'
python3 scripts/validation/analyze-track.py docs/temp/evidence/T-052/RUN
./scripts/kanban check
```

`analyze-track.py` sums independent GLOBAL_POSITION_INT great-circle distance
across the accelerate-north through pre-interruption settle interval, reads
the rendered Flown text from the live and replay browser captures nearest the
comparison instant, and checks the largest backward step within the steady
northward corridor. Gates: live/replay Flown within 5 m of the raw route;
backward track steps no larger than 0.2 m (or the raw stream's own backstep,
whichever is larger); live sample within 0.5 s and replay within 1.5 s of the
comparison instant; zero browser runtime exceptions.

## observe-motion.mjs fix

The first attempt at this run (`2026-09-15-r1-incomplete`) captured a live
browser session that never opened the vehicle detail panel: the script's
non-replay branch clicked "Open selected vehicle" exactly once, immediately
after the map element first appeared, with no check for the button's
`disabled` state. On this run the fleet's bootstrap had not yet reported any
vehicle (and the current backend also carries an unrelated stray `250:0`
entry — a separate observation, not investigated here), so the button was
disabled at click time; the click was a silent no-op and the Flown readout
never rendered for the rest of the capture. Fixed by polling for the button
to become enabled the same way the replay branch already polls for "Play",
instead of clicking unconditionally once.
